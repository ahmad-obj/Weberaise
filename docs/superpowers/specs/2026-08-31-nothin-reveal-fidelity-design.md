## 1. Goal

The current WEBERAISE hero is structurally successful. The loader, opening choreography, registered front/reveal typography, navigation, EXPLORE transition, main-page handoff, responsive behavior and fallback system already exist and should not be redesigned as part of this change.

The requested improvement is specifically the interactive mask:

> Replace WEBERAISE's rounded/metaball-like reveal character with a reveal that behaves substantially like the fluid mask on `https://www.noth.in/`.

The target is not a generic "fluid-inspired" effect. The target is Nothin's observable material behavior: directionally transported liquid, thin/irregular connected regions, smooth bending, organic deformation generated by the fluid itself, and a near-binary reveal boundary.

## 3. Executive finding

The central result is now confirmed:

> **Nothin uses a genuine pressure-projected 2D fluid simulation. It does not construct the reveal from age-aware circles, metaballs, capsules or an SDF history.**

Nothin maintains persistent GPU fields for:

- velocity;
- dye/reveal density;
- pressure;
- curl;
- divergence.

Pointer movement injects both directional momentum and dye into those fields. The velocity field transports the dye over time. A pressure solve keeps the velocity approximately divergence-free. The final dye is then converted into a very hard/near-binary mask and used to reveal the visual underneath.

This is the fundamental reason Nothin's reveal can stretch, bend and deform directionally without reading as a chain of circles.

The current WEBERAISE implementation uses a different geometry family. Therefore this fidelity problem cannot be solved by merely tuning radius, threshold, lifetime or contour noise.

## 4. Nothin hero composition

The exported HTML has this relevant stacking structure:

1. `.section-w` — containing hero environment;
2. `.video-hero-bg` — autoplaying full-width hero video behind the mask;
3. `.section.hero-home` — white hero foreground;
4. `.nothin-hero-svg` — foreground NOTHIN wordmark;
5. JavaScript inserts `.mask-reveal-canvas` between the video and hero section.

When the fluid engine is initialized, the NOTHIN SVG is rasterized into the WebGL base texture on white. The reveal texture is transparent. The original SVG is then hidden.

The final shader mixes:

`base texture → transparent reveal texture`

using the fluid mask.

Because a video is physically behind the canvas, transparency exposes the moving video only where the fluid mask is active.

This composition differs from WEBERAISE's current inverse black/white DOM composition, but the important reusable part is the **fluid mask**, not Nothin's exact base/reveal layering.

WEBERAISE should retain its own registered typography/logo compositor and feed it the Nothin-style simulated mask.

## 5. Nothin renderer configuration

The shipped bundle carries Three.js revision `184` and creates a dedicated `WebGLRenderer` for the reveal.

Renderer characteristics:

- antialiasing disabled;
- alpha enabled;
- premultiplied alpha disabled;
- high-performance GPU preference;
- clear alpha of zero;
- automatic clearing disabled;
- display DPR capped at `2`.

This is a useful signal: Nothin does not spend multisample AA cost on the simulation canvas. Surface quality comes from the dye field resolution and mask threshold rather than MSAA.

| Setting | Nothin production value |
| --- | ---: |
| Simulation resolution | `256 × 256` |
| Dye resolution | `512 × 512` |
| Velocity dissipation | `0.962` per simulation frame |
| Dye dissipation | `0.988` near hero top |
| Pressure iterations | `20` |
| Curl strength | `0` |
| Splat radius parameter | `0.00006` |
| Splat force | `5900` |
| Reveal multiplier | `3.9` |
| Mask threshold start | `0.5` |
| Mask threshold width | `0.01` |

The render-target structure is:

### Velocity

- double/ping-pong framebuffer;
- `256 × 256`;
- linear filtering;
- RGBA half-float texture.

### Pressure

- double/ping-pong framebuffer;
- `256 × 256`;
- nearest filtering;
- RGBA half-float texture.

### Dye

- double/ping-pong framebuffer;
- `512 × 512`;
- linear filtering;
- RGBA half-float texture.

### Curl

- single framebuffer;
- `256 × 256`;
- nearest filtering;
- RGBA half-float texture.

### Divergence

- single framebuffer;
- `256 × 256`;
- nearest filtering;
- RGBA half-float texture.

This is substantially more stateful than WEBERAISE's current single RGBA8 field target.

## 7. Nothin pointer input

The reveal listens globally to:

- `mousemove`;
- `touchmove`.

Coordinates are normalized into the reveal canvas:

- X from left to right;
- Y flipped so zero is at the bottom in fluid UV space.

The engine remembers the previous sampled mouse position.

For each simulation step with a changed pointer:

`delta = currentPointer - previousPointer`

The same pointer event generates two splats.

### Velocity splat

The velocity field receives approximately:

`pointer delta × 5900 × scrollFade`

X is aspect-corrected in the splat shader so the brush remains spatially consistent across viewport aspect ratios.

### Dye splat

The dye field receives a white scalar injection multiplied by the same scroll-fade factor.

The splat profile is Gaussian rather than a hard disc. Its field falls exponentially with squared distance from the pointer.

There is no long-lived CPU list of pointer circles.

Once injected, the input becomes part of the persistent GPU field.

---

## 8. Important difference: no explicit pointer-trail primitive history

Nothin does **not** preserve the trail by storing hundreds of old pointer points and redrawing them every frame.

It stores the result of the interaction in textures.

This means:

- pointer geometry is deposited once;
- the dye itself persists;
- velocity transports the deposited dye;
- old geometry can deform continuously;
- the shape is no longer tied to its original circular splat after deposition.

This is the architectural behavior WEBERAISE currently lacks.

WEBERAISE's pointer interpolation can still be retained as an input-quality improvement, but interpolated samples should be **deposited into the simulation**, not kept as the visible geometry model.

---

## 9. Nothin fluid step — confirmed order

The production engine executes essentially the following sequence every animation frame.

### 9.1 Pointer injection, when needed

1. Compute pointer delta.
2. Splat directional force into the velocity field.
3. Swap velocity read/write targets.
4. Splat dye into the dye field.
5. Swap dye read/write targets.

### 9.2 Curl field

Compute scalar curl from the neighboring velocity samples.

### 9.3 Vorticity pass

The engine contains a vorticity-confinement shader and runs it.

However:

> **The production setting uses `curlStrength: 0`.**

So Nothin deliberately disables added swirling/turbulence in the default reveal.

This is a critical design signal. The fluidity comes from advection and pressure-constrained momentum, not from decorative vortices.

### 9.4 Velocity advection

The velocity texture is advected through itself.

The shader manually bilinearly samples the source field and multiplies it by velocity dissipation.

Production retention:

`0.962` per frame.

This is relatively aggressive velocity damping, which explains why motion settles rather than swimming indefinitely.

### 9.5 Dye advection

The dye texture is advected using the current velocity field.

Near the top of the hero:

`dye retention = 0.988` per frame.

The dye therefore survives much longer than momentum.

This difference is important:

> **The shape remains visible after the motion that formed it has mostly settled.**

### 9.6 Divergence

The divergence of the current velocity field is computed from neighboring velocity samples.

### 9.7 Pressure reset

The pressure read target is cleared before solving each frame.

### 9.8 Pressure solve

Nothin performs `20` Jacobi pressure iterations per frame.

Each iteration reads neighboring pressure values plus divergence and writes a corrected pressure field, then swaps the pressure targets.

### 9.9 Gradient subtraction

The pressure gradient is subtracted from velocity.

This produces the pressure-projected velocity used as the persistent motion state for subsequent frames.

### 9.10 Final composition

The dye texture is supplied to the final mask material and the hero is rendered.

## 10. Nothin mask extraction — why the edge looks solid

Nothin does not display the dye as translucent smoke.

The final material samples the red channel of the dye texture and then applies:

- a reveal gain of `3.9`;
- a `smoothstep` beginning at `0.5`;
- an extremely narrow transition width of only `0.01`.

Equivalent dye values for the transition are approximately:

- mask begins near dye `0.1282`;
- mask becomes fully revealed near dye `0.1308`.

That transition band is extremely narrow.

The result is effectively:

`fluid density → hard liquid surface`

rather than:

`fluid density → translucent fog`.

This is one of the most important fidelity details.

---

## 11. Nothin's organic contour does not come from procedural noise

The supplied mask fragment shader contains no FBM, simplex noise, hash noise or animated sine contour distortion.

The organic perimeter comes from:

- Gaussian dye injection;
- persistent velocity;
- advection;
- pressure projection;
- dissipation;
- thresholding the resulting dye field.

Therefore WEBERAISE should not attempt to recreate Nothin by increasing contour noise.

Our existing compositor's animated sine threshold warp should be removed or reduced to zero in the Nothin-fidelity full-quality mode unless later side-by-side testing demonstrates a small WEBERAISE-specific benefit.

The simulation should create the shape.

---

## 12. Nothin healing / disappearance

Nothin does not heal by shrinking the original splat geometry.

Dye is continuously multiplied by dissipation while it is being advected.

As field strength falls below the narrow final mask threshold, areas disappear from the reveal.

This gives a fundamentally different restoration model from WEBERAISE:

### Current WEBERAISE

`old pointer circle → hold → circle radius shrinks → disappears`

### Nothin

`deposited dye → transported/deformed field → field amplitude decays → threshold surface contracts/breaks → disappears`

This is why Nothin's old shape can taper, split and deform without exposing the construction primitives.

---

## 13. Approximate persistence interpretation

Nothin's production dissipation values are frame-based rather than delta-time-corrected.

At a 60 Hz reference cadence:

- velocity retention `0.962` corresponds to a velocity half-life of roughly `0.30 s`;
- dye retention `0.988` corresponds to an amplitude half-life of roughly `0.96 s`.

Because the visible dye threshold is only around `0.128–0.131`, a single strong dye value starting near `1.0` remains above the visual mask threshold for roughly `2.8 s` at 60 Hz before accounting for overlapping deposits and advection.

This closely explains the observed several-second trail without explicit per-primitive lifetimes.

### WEBERAISE improvement

We should match Nothin's **60 Hz visual timing** but make retention frame-rate independent:

- velocity retention equivalent: `pow(0.962, deltaSeconds * 60)`;
- dye retention equivalent: `pow(0.988, deltaSeconds * 60)`.

This keeps the Nothin material character while preventing 120 Hz displays from healing much faster than 60 Hz displays.

---

## 14. Scroll-aware fade in Nothin

Nothin reduces the fluid interaction as the user scrolls away from the hero.

It computes hero scroll progress approximately as:

`clamp(-canvasTop / canvasHeight, 0, 1)`

Then squares that progress and derives an interaction factor:

`interaction = 1 - progress²`

This factor scales:

- pointer velocity injection;
- pointer dye injection.

Dye dissipation also changes from `0.988` toward `0.97` while leaving the hero, making old reveal content clear faster.

This is a smart lifecycle detail worth retaining conceptually if WEBERAISE ever allows the interactive hero to coexist with scrolling. Our current ExperienceShell exits the hero before main scrolling, so this exact scroll coupling is not required for the current architecture.

---

## 15. Nothin simulation deliberately avoids excess turbulence

The presence of curl/vorticity code in the bundle initially suggests a more turbulent solver.

The actual production setting resolves this:

`curlStrength = 0`

Therefore the visual target should be understood as:

- fluid transport: yes;
- incompressibility/pressure behavior: yes;
- persistent momentum: yes, but heavily damped;
- artificial vortex amplification: no;
- procedural noisy edge: no;
- broad watery waves: no.

This is exactly the restrained character needed for WEBERAISE.

## 16. Current WEBERAISE reveal — architecture

The current code path is primarily:

- `src/components/experience/Hero/HeroRevealCanvas.tsx`
- `src/webgl/reveal/RevealEngine.ts`
- `src/webgl/reveal/shaders.ts`
- `src/webgl/reveal/quality.ts`
- `src/webgl/reveal/liquidLifetime.ts`
- `src/webgl/reveal/inertia.ts`

### Current field model

WEBERAISE owns one low-resolution RGBA8 render target.

Each frame:

1. all still-alive CPU primitives are collected;
2. each primitive radius is calculated from age;
3. the field framebuffer is cleared;
4. every active primitive is drawn additively;
5. the accumulated field is thresholded into the visible reveal.

The field itself has no temporal memory.

### Current primitive model

Every sample is fundamentally radial.

Velocity only stretches the primitive by up to roughly 12%.

Overlapping radial fields create metaball-like necks.

### Current healing

Old samples stay full-sized for a hold fraction and then the circles themselves shrink.

### Current afterglide

When pointer motion stops, a few smaller satellite primitives are emitted along the previous direction.

Those satellites add more circular islands rather than deforming one persistent mass.

## 17. Confirmed root cause of WEBERAISE's current visual mismatch

The "too roundy / too blobby" appearance is architectural.

WEBERAISE is biased toward rounded forms by:

1. radial basis primitives;
2. additive metaball union;
3. weak velocity anisotropy;
4. geometric circle shrinkage during healing;
5. no persistent velocity texture;
6. no persistent dye field;
7. no advection;
8. no pressure projection;
9. synthetic afterglide circles;
10. contour motion added cosmetically after geometry generation.

Nothin's field, by contrast, remains free to deform after pointer deposition.

No reasonable amount of tuning to the existing metaball model can make it faithfully behave like the Nothin production effect.

## 18. Locked implementation direction

Direct bundle evidence resolves the architecture decision that was previously provisional.

### Full-quality desktop mode

WEBERAISE should use an independently implemented **pressure-projected 2D fluid reveal inspired by the confirmed Nothin pipeline**.

Start from the Nothin production structure rather than another experimental hybrid:

1. persistent velocity ping-pong target;
2. persistent dye ping-pong target;
3. divergence target;
4. pressure ping-pong target;
5. optional curl target for architectural parity, while default curl strength remains zero;
6. Gaussian pointer splats;
7. velocity advection;
8. dye advection;
9. pressure solve;
10. gradient subtraction;
11. very narrow dye threshold;
12. existing WEBERAISE front/back compositing.

The fluid algorithm can be independently implemented from standard stable-fluid techniques. Do not copy Nothin's minified production source into the repository.

## 20. Where WEBERAISE may intentionally improve on Nothin

Similarity of material behavior is the goal; implementation defects do not need to be copied.

### 20.1 Frame-rate independence

Nothin's dissipation is frame-based.

WEBERAISE should convert it to time-corrected retention while preserving Nothin's 60 Hz appearance.

### 20.2 Pointer interpolation

Nothin primarily splats the latest pointer location and pointer delta seen by the simulation frame.

WEBERAISE already has robust path interpolation.

Retain interpolation for very fast mouse motion, but change its role:

- interpolated points become multiple simulation splats;
- they do not become long-lived CPU geometry;
- injection strength must be normalized so additional interpolated points do not accidentally make fast movement much denser than Nothin.

### 20.3 Adaptive quality

Nothin uses one main simulation profile.

WEBERAISE should retain explicit quality tiers for weak GPUs/mobile while keeping the same field semantics.

## 24. EXPLORE transition compatibility

The current reveal engine also owns the black bottom-fill transition used when EXPLORE exits the hero.

The fluid rewrite must not couple that authored transition to the fluid solver.

Recommended separation:

- interactive phase: fluid dye mask drives local reveal;
- hero exiting phase: stop accepting fluid input and keep/freeze the solver as appropriate;
- bottom-fill remains an explicit authored full-screen transition in the composite shader or a separate pass;
- once fill reaches completion, stop/destroy heavy fluid work before the main stage.

This preserves the accepted hero choreography while replacing only the interactive material behavior.

## 25. Quality tiers

### Full

Start from Nothin fidelity:

- 256 simulation;
- 512 dye;
- 20 pressure iterations;
- half-float render targets;
- zero curl strength;
- full advection and projection.

### Lite

Same semantic model with reduced cost, for example:

- 128–192 simulation;
- 256–384 dye;
- fewer pressure iterations after visual testing;
- zero curl;
- same narrow threshold.

Do not replace lite mode with obvious circle metaballs unless actual hardware limitations make fluid render targets impossible.

### Reduced motion

Keep input-driven reveal but suppress autonomous/scripted post-motion and shorten residual transport. The mask may use a simplified persistent-dye path if appropriate.

### No usable float/half-float render targets

Fall back deliberately to the current CSS/restrained reveal rather than attempting an unstable solver.

## 26. GPU capability requirements

The native WebGL2 implementation must explicitly probe the formats required by the solver.

The preferred path uses renderable half-float textures for signed velocity and smooth field evolution.

Before enabling full mode verify:

- WebGL2 context;
- renderable half-float/float color attachments as required;
- framebuffer completeness for chosen formats;
- linear sampling support for the selected half-float format/path.

Do not assume desktop support implies mobile support.

## 27. Loader warm-up

WEBERAISE already warms its reveal engine during the truthful loader.

The new solver should preserve and expand this.

Warm-up should include:

- WebGL context acquisition;
- shader compilation/linking;
- all render-target allocations;
- framebuffer completeness checks;
- a tiny offscreen/dummy execution of the pass graph where practical.

The first pointer interaction must not compile twenty-plus fluid passes on demand.

## 28. Performance interpretation

The Nothin pipeline is deliberately low-resolution where physics is expensive:

- pressure/velocity work occurs at 256²;
- visually important dye occurs at 512²;
- display rendering happens only once after the field passes;
- antialiasing is disabled;
- curl amplification is disabled.

This is why a 20-iteration pressure solve remains practical.

WEBERAISE should follow the same cost distribution rather than attempting fluid physics at display resolution.

## 29. Visual acceptance criteria

The implementation is not accepted merely because the solver is technically correct.

### Shape

- A normal stroke must stop reading as a chain of circles.
- Fast motion should stretch the liquid in movement direction.
- Curves should bend one connected mass rather than place bulb after bulb.
- Narrow regions may taper, stretch and break organically.
- Overlapping paths should merge through the evolving dye field.

### Motion

- Pointer response feels immediate.
- Residual motion continues briefly because velocity remains in the field.
- Residual motion damps quickly rather than swimming indefinitely.
- No synthetic satellite droplets are required for basic inertia.
- No visible high-frequency turbulence.

### Edge

- Interior reveal appears solid.
- Boundary is narrow and clean.
- Organicity comes primarily from the simulated field.
- No obvious sine/noise animation crawling around the perimeter.
- No fog halo.

### Healing

- Old reveal loses strength naturally through dye dissipation.
- Surface contraction does not look like individual circles shrinking.
- Old regions may taper or split before disappearing.
- Approximate perceptual lifetime should begin close to Nothin's several-second behavior.

### Registration

- WEBERAISE front/reveal typography remains pixel-registered.
- Logo placement does not drift on resize.
- Fluid simulation never blurs actual typography; only the mask edge is continuous.

## 32. Things we should NOT copy from Nothin blindly

### Frame-based dissipation

Match its 60 Hz appearance, but make timing frame-rate independent.

### Exact hero compositing

Nothin reveals transparency over video. WEBERAISE has a different inverse-layer composition. Reuse the mask behavior, not the surrounding art direction.

### Lack of pointer interpolation

WEBERAISE can retain its interpolation if injection is normalized correctly.

### Unnecessary passes

Nothin still computes curl and runs vorticity even though production curl strength is zero. During implementation we may preserve architectural parity first, then remove the no-op pass only after verifying it cannot alter output and after performance comparison.

## 34. Final architecture decision

The supplied Nothin bundle resolves the prior uncertainty.

The previous WEBERAISE architecture decision:

`pointer history → age-aware radial primitives → thresholded metaball surface`

should be superseded for the full-quality hero reveal by:

> **Pointer splats → persistent half-float velocity + dye fields → advection → pressure projection → dye dissipation → narrow threshold → WEBERAISE compositor.**

This is not merely a more sophisticated implementation. It is the geometry model needed to enter the same visual family as Nothin.
