# Services Capabilities + Silk Refinement Design

## Status and authority

This document is an approved refinement to `docs/superpowers/specs/2026-08-14-services-capabilities-silk-design.md`.

Where this document conflicts with the earlier spec, **this document wins**.

Implementation baseline:

- branch: `feature/services-opening-grid`
- baseline head before this refinement: `fd4f261a6b168a82a447f41d52fa138b346c98cb`
- current Silk implementation: `src/components/ui/SilkWavesBackground/*`
- current Capabilities implementation: `src/components/ServicesPage/CapabilitiesSection*`, `capabilitiesModel.ts`
- the final Contact CTA remains deliberately undesigned and out of scope; preserve the existing downstream reserve only.

## Reason for refinement

Browser review showed two clear issues:

1. the current custom Silk approximation does not match the approved Silk reference closely enough;
2. the capability names are too scattered and visually disconnected.

The refinement therefore tightens both systems rather than changing the overall page concept.

## Shader source of truth

The user supplied an exact WebGL1 `Silk` fragment shader generated by the 21st.dev Shader Builder, including the packed-uniform contract and preset values. That supplied source is the implementation source of truth for shader mechanics.

Do not keep the current simplified custom `fbm + ridge` approximation.

The implementation must use the supplied shader logic exactly, while changing only the colour palette to the approved Weberaise blue-oriented palette below and retaining the already-approved fixed-canvas page integration.

### Geometry

Use one fullscreen triangle in plain WebGL1, no shader library:

```ts
new Float32Array([
  -1, -1,
   3, -1,
  -1,  3,
])
```

Draw with:

```ts
gl.drawArrays(gl.TRIANGLES, 0, 3);
```

### Packed uniform contract

The fragment program exposes:

```text
u_colors[8]
u_scene
u_shape
u_surface
u_finish
u_transform
u_space
u_cursor
```

Uniform values must match the supplied Silk preset mechanics:

```text
u_scene     = vec4(canvas width, canvas height, seconds * 0.76, 4.0)
u_shape     = vec4(1.26, 0.28, 0.50, 0.00)
u_surface   = vec4(2.40, 1.11, 0.00, 1.00)
u_finish    = vec4(0.00, 0.00, 0.000, 0.05)
u_transform = vec4(1581.0, 0.00, 0.00, 0.0)
u_space     = vec4(0.00, 0.00, 0.00, 0.00)
u_cursor    = vec4(0.00, 2.0, 0.65, 0.46)
```

This corresponds to the approved reference feel:

- speed: 35/100;
- zoom: 38/100;
- intensity: 28/100;
- warp: 0/100;
- contrast: 57/100;
- brightness: 50/100;
- saturation: 50/100;
- hue: 0 degrees;
- vignette: 0/100;
- grain: 14/100;
- cursor: off.

### Weberaise blue palette

Replace the reference purple palette with this four-stop palette, low to high:

```text
#01040A
#03132D
#0A3D91
#2878F6
```

Normalized sRGB values:

```text
vec3(0.003922, 0.015686, 0.039216)
vec3(0.011765, 0.074510, 0.176471)
vec3(0.039216, 0.239216, 0.568627)
vec3(0.156863, 0.470588, 0.964706)
```

Only the first four entries of `u_colors[8]` are active because `u_scene.w` is `4.0`. Set the unused four entries deterministically, preferably to the final active colour, rather than leaving undefined uniform values.

The result should read noticeably more blue than the current implementation while preserving deep black/navy lows and avoiding purple drift.

## Shader interaction and motion

The cursor is now **fully off**.

This supersedes the earlier weak-pointer-influence decision.

Therefore remove:

- pointermove listeners;
- pointerleave listeners;
- pointer damping state;
- `dampScalar` usage for the Silk background;
- fine-pointer media-query logic used only by the Silk shader.

`u_space.zw` stays `0,0` and `u_cursor.x` stays `0`.

The shader remains autonomous and independent of page scroll.

## Fixed background integration

The already-approved architecture stays:

- one fixed viewport canvas;
- shared by Capabilities and the future Contact CTA;
- upstream Works area visually hides it with true black;
- the existing long black-to-Silk transition veil remains;
- shader does not restart at section boundaries.

The supplied generic integration note that mentions an absolutely positioned canvas does **not** override this site-specific fixed-canvas decision.

## Lifecycle and performance

Preserve the current good lifecycle behavior:

- pause RAF while `document.hidden`;
- use `IntersectionObserver` to avoid running far from the Services tail;
- keep `rootMargin` valid CSS pixels/percent only;
- handle `webglcontextlost` by falling back safely;
- keep a deterministic static fallback;
- freeze to a deliberate static frame for `prefers-reduced-motion: reduce`.

Render sizing changes to match the supplied reference requirement:

```ts
const dpr = Math.min(Math.max(devicePixelRatio || 1, 1), 2);
```

No separate coarse-pointer DPR cap is required for this refinement. Browser profiling may justify a later quality tier, but visual parity is the current priority.

## Capabilities composition refinement

The scattered `left / mid / right` positioning is removed completely.

The section remains editorial, spacious and Kue-inspired, but becomes visibly organized.

Each discipline is one clear horizontal group:

```text
01 // DESIGN

Art Direction                  UI/UX
Responsive                     Motion
```

```text
02 // DEVELOPMENT

Frontend                       CMS
Integrations                   E-commerce
```

```text
03 // IMPROVEMENT

Performance                    SEO Foundations
Analytics                      Iteration
```

### Layout rules

Desktop and suitable tablet widths:

- each discipline uses a consistent two-column, two-row grid;
- row and column rhythm is shared across all three disciplines;
- capability names align to the same invisible column system;
- no arbitrary percentage offsets;
- no staggering one item deep into the far right edge;
- no cards, boxes, borders around individual items, or pills;
- the discipline label remains above its own 2x2 grid;
- negative space comes from group spacing and generous row gaps, not random placement.

The content order remains DOM/read order:

1. first row left;
2. first row right;
3. second row left;
4. second row right.

### Desktop proportions

Use a full-width content grid with two balanced columns. A sensible starting point is:

```css
grid-template-columns: repeat(2, minmax(0, 1fr));
column-gap: clamp(56px, 8vw, 140px);
row-gap: clamp(34px, 5svh, 58px);
```

Capability typography should remain large but slightly calmer than the current screenshot if needed to keep the 2x2 structure visually coherent:

```css
font-size: clamp(40px, 4.7vw, 76px);
```

Exact type size is still tunable during browser QA.

### Tablet/mobile

At widths where two columns become cramped, especially around long labels such as `SEO Foundations`, collapse to one column.

Recommended breakpoint range: approximately 680-760px, tuned in browser.

Mobile becomes:

```text
01 // DESIGN
Art Direction
UI/UX
Responsive
Motion
```

with consistent spacing and no indentation tricks.

No horizontal overflow is acceptable.

## Capability interaction

Keep the approved subtle typography-only hover.

On fine pointer:

- small weight increase;
- tiny tracking compression;
- at most a 2-4px horizontal translation.

Do not use hover to disturb the organized grid.

On coarse pointer and reduced motion, keep the items static.

## Vertical scale

The earlier 130-160svh target still applies as a composition range, but the organized groups should determine the actual content height.

Do not force scatter-like empty zones simply to hit a viewport number.

The final Contact CTA remains out of scope. Preserve the existing blank reserve after Capabilities so that the shader environment continues into the future CTA area.

## Updated explicit non-goals

Do not:

- keep the current simplified custom Silk shader;
- approximate the supplied shader with another procedural effect;
- keep pointer influence;
- preserve `left / mid / right` item positions;
- scatter capability names;
- create a masonry/editorial scatter layout;
- add per-capability cards;
- design or implement the final Contact CTA;
- alter the Works Bridge or service-index choreography.
